    • vAlign

    The vAlign command rotates selected objects in World XY by aligning a hovered target curve to a clicked stationary reference, with faded live preview and optional separation distance.

    Steps

    1. Preselect objects or run vAlign and select the objects to rotate. Group members are treated as one movable object.
    2. Click the stationary reference curve or surface/polysurface edge near the end that should receive the target, or press Enter to use World Ortho. Kinks of 30 degrees or more are independently selectable segments.
    3. Hover a target curve or edge within the movable selection. The target is highlighted and the complete transformed result previews faded. With a reference, a thin line connects the picked points and moving the cursor across the target controls the rotation/offset side; hold Shift or Ctrl to reverse that side. Click any stationary curve or edge during this stage to replace the reference, including clicking the current reference near its other end. Without a reference, the target aligns vertically by default and horizontally while Shift or Ctrl is held, with cursor side choosing the direction. Click the target to apply the preview.
    4. Alignment uses World XY rotation around World Z, independent of the active view. Open curves match the clicked ends so the objects are not inadvertently reversed.

    Command-line options

    Distance

    a non-negative separation from a selected reference edge. Cursor side controls the destination side. Enter None to rotate in place around the selected objects' center of mass without translating them. Accepted changes, including None, persist between runs and Rhino sessions even if the command is later canceled. Distance is ignored in reference-free World Ortho mode.

    Loop

    Yes by default. After each alignment, selection is cleared and the command asks for objects, a reference, and a target again. Preselection is accepted only for the first cycle. No finishes after one alignment. Press Esc to finish the loop; completed alignments remain.

    SaveDefaults

    Yes by default. Set No before entering temporary Distance or Loop values, including in a macro. Temporary choices last for this run and do not change saved defaults; this toggle resets to Yes at the next run. Switching back to Yes saves the current choices.

    vBiminiParts

    The vBiminiParts command builds bimini cover pocket parts (facings, main pocket, secondary pockets, center reference line) from a selected boundary curve; pipe size configures pocket depths.

    Steps

    1. Select bimini boundary curves (preselect supported).
    2. The command joins the selected curves into a single closed boundary, then determines the seam curve (outward offset) and finished curve (either detected from an existing curve on the PLOT layer or computed as an inward offset), and breaks both at corners into top/bottom/left/right segments.
    3. Stage 2 — Main pocket: click the center of up to 2 seam or finished top/bottom segments to identify the main pocket side(s). Press Enter to skip.
    4. Stage 3 — Secondary pocket: click the center of remaining top/bottom segments for secondary pockets if fewer than 2 main pockets were picked. Press Enter to skip.
    5. Before generating a secondary pocket, its length calculated from the main curve is compared with the previous secondary-pocket length stored in the Rhino document. When they differ, the command shows both lengths and asks whether to reuse the previous length. A successfully created secondary pocket updates the stored document value.
    6. Output is built automatically:
    • Facing parts (port and starboard sides) with interior objects collected.
    • Main pocket outline — closed filleted rectangle trimmed to the boundary.
    • Secondary pocket outline(s) — closed filleted shapes with seam clearance.
    • Center reference line through all pocket center points.
    1. Output layers: PLOT (finished curve segments), CUT1 (seam and pocket outlines), Reference (center points and center line).
    2. Standalone generated curves inherit the selected boundary curves' groups. Facing and pocket parts remain in their own generated groups.

    Command-line options

    PipeSize

    selects a pipe size group which sets MainPktDepth, SecPktDepth, and optional ExtraRect dimensions. All groups are configurable in vTools.config.json under vBiminiParts.

    vCenter

    The vCenter command places a point at the combined bounding-box center, weighted mass center, or equal-weight object center of an editable geometry selection.

    Steps

    1. Preselect geometry or select it after running vCenter; add or remove individual objects before pressing Enter, with group selection matching vFitBox.
    2. A point preview updates as the selection changes.
    3. Set Method from the option list or type BoundingBox, Mass, or Objects directly. The selected method is saved immediately.
    4. Press Enter to place a normal Rhino point on the current layer while preserving the source selection.

    Methods

    BoundingBox

    center of the combined world-coordinate bounding box.

    Mass

    volume-weighted center for solids, otherwise area-weighted center, curve-length-weighted center, or the available point/fallback center.

    Objects

    equal-weight average of each selected object's natural volume, area, length, point, or bounding-box center.

    vChamfer

    The vChamfer command adds a chamfer line perpendicular to the middle curve at an equidistant gap; places the chamfer where the gap between two diverging curves equals the specified length.

    Steps

    1. Pick curve 1 — near the corner of the two diverging curves. For one closed curve, pick it near the corner to chamfer; the closest G1 kink is used and the second-curve prompt is skipped.
    2. For open curves, pick curve 2 near the same corner.

    Command-line options

    Length

    the desired chamfer line length — the perpendicular (equidistant) gap between both curves at the chamfer point. The chamfer is placed where the equidistant gap equals this value, with the line perpendicular to the middle curve.

    Trim

    Yes trims both curves to the chamfer endpoints; No only adds the line.

    Join *(Trim=Yes only)*

    Yes joins trimmed curves and the chamfer line into a single polycurve.

    1. Optional — pick a reference point to reposition the chamfer: click anywhere near the curves. The chamfer moves to the arc position where the chamfer line's midpoint is exactly Length units away from the click (toward the corner). Press ClearPoint to revert to the gap-based placement.
    2. Press Enter to apply.

    Notes

    • Open-curve corner detection uses the closest endpoint pair. Closed-curve detection uses the G1 corner closest to the cursor and rebuilds the same object around the chamfer. Extension stubs (toward a virtual corner) are shown in the preview when Trim=Yes and the cut falls inside the extension zone.
    • All options persist to vTools.config.json under vChamfer.

    vCleanup

    The vCleanup command simplifies scoped curves, finds covered overlaps, and identifies or deletes protected short segments and control-point candidates.

    Steps

    Shared overlap detection ignores nest table frames, dividers and label decorations, without excluding the parts inside those tables. Empty native overlap intervals and coverage projections that collapse to one point are not counted as overlapping sections, so cleanup and export use the same findings.

    Choose OrphanPartData at the selection prompt to run data-only cleanup without simplifying, deleting or selecting geometry. It scans saved part settings, custom fields and display names, then reports the number of orphaned part records and entries. Choose Delete to remove them or Cancel to leave them untouched. Active groups, existing boundary objects, unknown keys and records referenced by placed nesting output are retained, including hidden and locked objects and block-definition contents. Undo restores the removed entries. This action is never run automatically by normal cleanup or export optimization.

    1. Preselect curves or add/remove individual curves at the command prompt. Press Enter with no curve selection to process every curve object in the document.
    2. Press Enter after selection to approve and run cleanup.
    3. Enabled processing runs in order: SimplifyCrv-compatible curve simplification, shared vOverlaps detection, then short segment and adjacent control-point analysis. Open-curve endpoints remain protected.
    4. Review the surviving highlighted, selected, or named-selection findings.

    Command-line options

    Threshold

    maximum short-geometry length in model units; the default is 0.02.

    HighlightShort

    highlights surviving short findings in magenta and overlaps in cyan until the next vCleanup run. Highlights follow completed drawing edits, disappear when repaired, and return if Undo restores the issue.

    Preselect

    selects surviving Short, Overlaps, All, or No findings after deletion.

    AutoDelete

    deletes Short, Overlaps, All, or No findings. Any deleting mode runs SimplifyCrv once more afterward when simplification is enabled.

    SimplifyCrv

    runs Rhino-compatible curve simplification before analysis and, when deleting findings, once more afterward.

    Overlaps

    runs shared vOverlaps detection before the short-geometry scan.

    OverlapSegments

    when Yes (the default), splits the chosen source of a partial overlap and selects or deletes only its exact overlapping piece; No targets the chosen whole source curve. This setting is shared with vOverlaps.

    With AutoDelete=No, results are saved as the document named selections vCleanup Short geometry and vCleanup Overlaps. All settings persist.

    vCleanup, vExportDXF, and vExportPatternSmith use the same finding display: magenta for short geometry, cyan for overlaps, with a contrasting outline. Curves that become subpixel at distant zoom levels receive a fixed-screen-size cue. Existing cleanup color/size preferences are shared; outline and minimum-cue settings are available in vSettings under CleanupFindingDisplay.

    Starting any of these commands clears previous cleanup/export highlights. Press Esc three times quickly to dismiss their highlights and stop live tracking; single Esc still performs Rhino's normal cancellation. The maximum time between presses is configurable in vSettings under CleanupFindingDisplay.

    vExportPatternSmith

    The vExportPatternSmith command exports prepared parts and vNest table layouts directly as PatternSmith projects, with automatic material/table settings.

    Steps

    Enable Native seams and notches on the Preparation tab to export linked allowances and supported notches as editable PatternSmith effects. The default is off. Imported seam end styles are reused when they reproduce the prepared path. When a native effect cannot match the unthinned prepared geometry on its mapped tools, its curves are exported instead. This option does not modify the Rhino drawing or change DXF export.

    Open cut paths export and copy with nesting disabled. The exporter keeps the actual curves and any existing table placement without adding closing cuts.

    The export window stays open until export succeeds. It shows the current stage, progress, elapsed time and estimated time remaining; Cancel or Esc stops the native writer without replacing the destination. The Preparation tab contains PS-only grain, origin, notch, curve, text and cleanup controls. These saved choices are independent of vExportDXF, vCleanup and vOverlaps. Export copies are prepared only after Export is clicked. Each table's vNest Gap is exported as project-local Copy spacing, and tables follow natural table-name order. Catalog defaults and part positions remain unchanged. Custom IDs use the short c0000-c9999 namespace, persist globally and are checked for collisions. Every project embeds a transparent PNG preview of its exported geometry, including unplaced original parts.

    vExportPatternSmith writes a native .project file directly from the same temporary export parts prepared by vExportDXF. Select the desired vNest tables or parts, run the command, and choose the destination filename. With no selection, it uses the same visible, unlocked document scope as vExportDXF.

    The command reuses saved vExportDXF preparation settings for grain removal, notch trim/split/join, non-cutting endpoint trim, optional cleanup, curve explosion, multiline text, and part grouping. Use -vExportPatternSmith to change those shared export options for a run. Source objects, selection, temporary layers, and document save state follow the existing export restoration behavior. DXF export schemes and an intermediate DXF file are not required.

    When parts belong to vNest tables, each table becomes a native PatternSmith nest with its vNest width/length and unchanged table-local placed parts. Pattern definitions are spaced by table in the upper workspace independently of native copy locations; compact table-information headers become Reference-only workspace patterns, never cutting copies. Names use saved part names or vNest's main-label rules, excluding notch labels. Table frames follow moved, rotated, and uniformly scaled vNest output; inconsistent frame transforms are rejected. Repeated physical copies currently become separate source patterns. Loose parts export in an unpopulated default nest.

    Lengths convert from document units to inches. Smooth sections export together as native splines even when Rhino stores them as several cubic spans. The exporter reuses the original spline fit points when they reproduce the curve; otherwise it fits a spline within the document tolerance. Max error (in) defaults to 0.010, retains endpoints and checks thinning against the original; zero disables thinning. Dense native seam or notch splines are thinned only when the regenerated paths still match the prepared geometry within document tolerance. Choose Bezier to retain exact cubic control points where possible. Both choices are saved and available in vSettings. Standalone lines, polylines, circles, arcs, text and points retain native representations. Invalid closed cutting outlines or outside internals are reported with the part/entity reason. Open cut paths keep their geometry and any existing placement but cannot be auto-nested.

    The Materials tab shows each Rhino material's mapped PatternSmith name, folder and ID in a persistent overview. Its expandable library tree preserves nested and empty folders, prioritizes Artful, supports search, and reveals the current mapped leaf when selecting a Rhino material. Choosing a folder never changes the assignment; choosing a material changes only the selected mapping. Stale saved mappings require review. Custom project materials receive random colors that remain remembered between exports. Every nonheader part receives its native material-ID constraint, not just a copy inside a material nest. The Layers map tab retains editable process/tool-slot assignments. With Remove grain enabled, grain-only rows remain visible but disabled. Unresolved mappings for exported layers stop export before the destination is replaced.

    Material lookup queries the already-running PatternSmith library server without launching it or writing catalog data. If unavailable, it reads the configured current .library file directly, then the PS10 library from Material.library.preferences, all read-only. vSettings exposes the server host, explicit library paths, limits and timeouts. Artful is the configurable preferred group; other groups remain available. Confirm each mapping or choose Project material only. Saved catalog mappings include their source, material name and group, and explicit project-only choices remain remembered. Existing catalog IDs, colors, spacing, speed, cost and power settings are retained, while project-local templates keep each vNest width without changing part positions. Catalog choices currently support solid roll materials; hides, stripes and plaids are not silently converted to plain rolls.

    Table headers export as editable Arial Regular text, retaining the original capitalization. Use Export to beside the filename to choose PatternSmith 10 or 11. The version is remembered and can also be set in vSettings. PatternSmith 11 receives physical point sizes; PatternSmith 10 receives its legacy editable sizing. Merge keeps existing labels unchanged and applies the selected version to new labels. Change the font family with TableLabelFontFamily in vSettings. The header frame fits the exported glyphs, and importing the project back into Rhino keeps the font and editable text. Part labels retain the existing PatternSmith stroke font. Mirrored labels export as curves because editable PatternSmith text cannot store a reflection. Entity/tool combinations unsupported by PatternSmith use its DXF-import fallback to Reference. PatternSmith automatic re-nesting is disabled for exported parts until vNest grain constraints are mapped; explicit table placements remain available.

    The compatibility writer uses installed PatternSmith 10.2.17.873 model libraries in an isolated hidden .NET Framework helper; the Rhino process never loads those vendor assemblies. Its source remains in the command's PATTERNSMITH_BUILDER section, while the binary belongs under Resources/PatternSmith, not Commands. Builds regenerate it deterministically when the matching SDK is installed; otherwise the source-hash check rejects a stale precompiled resource. Project validation uses constructors and plain XML, never vendor deserialization that could import into the workstation library. Live PatternSmith opening remains the final integration check.

    The vCopyToPatternSmith command prepares Rhino parts and loose geometry for Ctrl+V in PatternSmith 11.

    vImportPatternSmith

    The vImportPatternSmith command opens PatternSmith projects as Rhino parts and editable vNest tables.

    Steps

    Use vImportPatternSmith, Rhino File > Open or File > Import, or drop a PatternSmith .project into Rhino and choose the appropriate file action. For interactive opens, vFileTypeTemplate runs first so its layers are available in the mapping dialog, then the new drawing uses PatternSmith's native inches. The template's physical absolute tolerance is preserved. Import uses the current drawing's units without applying a template. In Materials map and Layers map, edit each destination directly on its row. The layer chooser uses the standard vTools dropdown with layer swatches and full paths. Unmapped project materials stay document-local; importing never changes either global material library.

    Opening a project maximizes the Top model viewport and zooms to fit the complete drawing. Importing into an existing drawing leaves its view unchanged.

    Table-info frames expand to fit the existing editable labels without changing their font or height. If a resized frame has insufficient clearance from nearby objects, the frame and its labels move together. Ordinary part geometry and layout are unchanged.

    Choose Contents in the import window. Parts only imports the workspace without creating tables. Nests only imports native nests and their copies without the workspace. Unnested parts + nests (default) imports the nests and only workspace patterns not used in any nest. All imports both the workspace patterns and the native nests, including both versions of nested parts. The importer remembers the last successful interactive choice and the Include empty nests preference; both are also available under vImportPatternSmith in vSettings and used for scripted imports.

    Nested copies retain their table-local positions, rotations and mirrors. A matching table-information label supplies each imported vNest header. When workspace parts are also imported, available table labels are retained in the workspace with them. Nests only does not add separate label frames. Projects without native nests are not converted into guessed tables. Editable vNest tables are stacked in one column per imported material, in their saved order within each column. Table dimensions and copy gaps remain unchanged, and the layout uses vNest's table spacing. Empty nests are skipped unless requested. Import converts inches to the document's units and maintains editable text and exact lines/arcs/Béziers. If an entity cannot be read or reproduced, the importer reports it and stops before writing a partial drawing. Native splines use PatternSmith's cubic segments when the installed compatibility libraries are available; otherwise they are rebuilt through the saved fit points and reported.

    Steps

    The vShade command repeatedly creates identified Reference-layer angle bisectors and perpendicular shade lines, with optional non-crossing connected boundaries.

    Steps

    Command-line options

    Offset

    sets the signed distance from the tangent-defined corner to the center of the perpendicular line. Positive offsets go toward the shade interior, including at reflex corners; negative offsets go in the opposite direction. When the selected source curves form a closed outline, that outline determines inward even along curved sides. Enter a number directly at either curve prompt to change it. Zero places the line at the corner and omits the bisector.

    Chamfer

    sets the total perpendicular cap width, centered on the bisector endpoint. Zero omits the perpendicular line. Existing saved Length values are read as Chamfer until changed.

    Reinforcement

    sets the radius of an arc centered at each perpendicular midpoint and ending on its two incident perimeter connections. Defaults to 6; zero disables these arcs. An arc is omitted until both connections exist or when the radius lies beyond either one.

    CreateReinf

    No by default; Yes creates a detached closed reinforcement part for each valid corner arc. Its outline follows the current finished boundary, including custom edited sides, without cut allowance, and uses CutLayer. Copies its corner label, groups each part separately, and moves it outward until its minimum clearance from the outer cut outline is 2 inches converted to document units. With no cut outline, clearance is measured from the finished boundary. Changing this option updates only detached reinforcement parts; it does not rebuild the shade or replace custom sides. Detached parts are excluded from shade splitting.

    • In vSettings, vShade > Shade Material defaults to the Paper preset, and Reinforcement Material defaults to Pink. Choose a vNest material preset or None. Split shade pieces inherit the main shade's assignment. When tuning existing parts, saved assignments are preserved.
    Label

    sets the next reinforcement label; Enter at its text prompt disables labels. A nonempty numeric or alphabetic suffix advances after each placed corner (for example, 1 to 2 or A to B). The next value is stored in the document and starts at 1 in each new document. Labels are 0.5 model units high, centered between a reinforcement arc and its perpendicular line, with the perpendicular line as the text's bottom direction. Numeric labels that could read as a different number upside-down receive a trailing orientation dot (for example, 6. and 9.). A corner without a valid reinforcement arc has no visible label.

    LabelPrefix

    literal text prepended to new corner labels; empty by default and Enter clears it. The prefix is saved separately from the incrementing Label value, so prefix A and Label 1 produce A1, A2, and so on. Existing corners retain their labels and prefixes when edited or continued. An empty Label still disables labels even when a prefix is set.

    Connect

    when Yes, rebuilds non-crossing perimeter connections among all placed corners, regardless of selection order. Ends belonging to the same source curve are matched first; remaining free ends are paired by proximity. With three or more corners, it closes the loop when valid connections exist, without requiring the first and last picks to share a source curve.

    Join

    when Yes, joins connected perpendicular caps and perimeter lines into curves; No keeps each segment separate. Bisectors and reinforcement arcs remain separate.

    FinishedLayer

    chooses the layer for perpendicular, connection, reinforcement-arc, label and joined-boundary geometry; *Current*, . or * follows Rhino's current layer. Shown immediately before CutLayer. Bisectors always use Reference; cut outlines and detached reinforcement outlines keep their separate CutLayer.

    UseCurve

    Yes by default; retains each shared nonlinear source side at its exact original position and shape, trimming it only at the corner-cap intersections and extending the caps to meet it. No, or a connection without a shared curved source, uses the generated Scallop setting. The choice is remembered when continuing a shade.

    Scallop

    when Yes, generates an arc bulging toward the shade interior for either offset sign; No generates straight connectors. Applies to sides without a source-curve profile or when UseCurve is off.

    ScallopSize

    sets each arc's midpoint bulge distance. Enter an absolute model-unit value such as 4 or a percentage of that connector's endpoint span such as 5% (the default). It must be positive; a size that makes scallops cross each other or a chamfer cap is rejected without replacing the existing result.

    CutOffset

    offsets each closed shade perimeter outward by this non-negative model-unit distance. Zero (the default) omits the cut outline; open intermediate perimeters do not produce one.

    CutLayer

    sets the layer for the outward cut outline. Defaults to CUT1, which is created only when a cut outline is produced and the layer does not exist.

    ScallopTune

    set ScallopSize in the tune prompt, or type a value such as 12% directly, then click perimeter sides to apply that size individually. 0 makes a clicked side a straight line; a positive model-unit value or percentage makes it an arc. Press Enter to return to corner selection. Individual choices are retained when the shade is continued later, even when Join combines the connectors into one boundary object. If source curves were joined later, vShade can recover a side that still has the original corner endpoints. If the side is ambiguous, vShade reports it without replacing the outline.

    • Tuning the original shade leaves copied shades and parts untouched. Detached reinforcement outlines and labels update at their current position and rotation, including pieces that have been moved away from the shade.
    OffsetTune

    set Offset in the tune prompt, then click a corner's bisector or perpendicular cap to move only that corner to the specified offset. The connected boundary, reinforcement, and cut outline update with it. Press Enter to return to corner selection.

    appears once a closed cut or shade boundary exists. Opens the same split review and placement workflow as vPartSplit, with vShade's saved SplitWidth (default 63 model units) and SplitSeamType (default Overlap). Split copies use the same cut planning, finished boundaries, seam allowances, notches and labels. Accepting placement finishes vShade; canceling returns to corner selection. The original shade stays in place. One native undo removes the split copies and their Reference cuts; the next undo reverses the original shade edits.

Ctrl+Z and Ctrl+Y step through placed corners and tune edits while the command remains active; neither appears as a command option. Connections that would cross existing perimeter lines are omitted. Main shade output except bisectors belongs to one shade group; detached reinforcement parts have their own groups.     The vTrim command trims and extends curves with auto-cutter detection and join of extensions.

    Steps

    1. Choose a workflow: select cutting curves for Regular mode, or press Enter for AutoClosest mode.

    Regular mode

    1. Select one or more cutting curves and press Enter.
    2. vTrim passes those cutters to Rhino's native Trim command, which handles target selection, preview, and trimming normally.

    AutoClosest mode

    1. Press Enter without selecting cutting curves.
    2. Hover a target curve. vTrim finds the nearest valid contact on each side along the curve and previews the exact portion that will be removed. Between two cutters, only the intervening section is removed; both outer sections remain.
    3. Press Tab to cycle through curves under the cursor. The whole-curve highlight and exact trim/extend preview identify the current target. A Tab-chosen curve remains preferred when you move away and return to the overlap, for the duration of this command run. Ctrl+Tab and Alt+Tab retain their normal behavior.
    4. Click to apply the displayed trim. Hold Shift before clicking to preview and apply an extension from the hovered end instead.
    5. Hold Ctrl to preview and trim that same section on every coincident curve at the cursor. Only actual 3D overlaps count, not crossings or curves at different depths. Other sections remain intact; a curve entirely covered by the removed section is deleted. The edit is one hidden local undo/redo step.
    6. Drag a box to preview multiple trim sections, then release to apply them together. A left-to-right box selects enclosed sections; right-to-left selects touched sections. Trimming uses existing cutter intersections and retains at least one section of each curve. Hold Shift when starting the box to extend open-curve ends inside it to their nearest forward cutters; a box containing both ends extends both. Intersections and extension plans are reused throughout the drag. One hidden local undo/redo step restores the entire box edit. Enter or Esc during a drag applies no box edit.
    7. Continue hovering and clicking targets, or press Enter when finished.

    In parallel plan views, AutoClosest also uses apparent intersections in the view direction, including curves at different depths. Angled and perspective views use 3D contacts only. Trimmed and extended curves keep their original 3D geometry rather than being flattened.

    AutoClosest options

    • Extend: Line or Smooth extension style.
    • Join: Yes or No for joining kept trim pieces.

    Preview colors

    • Entire affected curves: their original display colors, with bold strokes beneath the exact trim/extend preview.
    • Trim removal preview: red.
    • Extend addition preview: green.

    vTrimOff

    The vTrimOff command trims selected curves to the outer boundary of the enclosed region they collectively form; protruding ends are removed automatically.

    Steps

    1. Select at least 2 curves (open or closed, crossing or adjacent).
    2. The command finds all enclosed regions formed by the selected curves and computes their combined outer boundary.
    3. The original selected curves are replaced by the trimmed boundary curves; protruding ends that extend outside the enclosed region are discarded.
    4. Uses the active CPlane for planar region detection.

    vUnrollSrf

    The vUnrollSrf command unrolls selected surfaces through native UnrollSrfUV by default, or UnrollSrf with UV disabled; reruns preserve labels, shared-edge markers, part identities and prior flat placement.

    Steps

    1. Select surfaces, polysurfaces, or extrusions to unroll.
    2. Select curves, points, or dots that should follow their nearest surface, or press Enter for none.
    3. Choose the output start point. When replacing already processed parts, press Enter to preserve each part's prior position and orientation.
    4. Flat parts receive matching labels and shared-edge M### dots for use with vMatch. The default top-level output layers are Unrolled_surface, Unrolled_label, and Unrolled_dot, ordered immediately below Surface; missing layers are created only when their corresponding output is committed. Polysurface markers retain their source-edge face association and exact position on the corresponding flat edge. Text is fitted to the trimmed flat part and the same height is applied to its original-surface label. Planar single-face parts are mapped exactly. Ruled faces with a collapsed apex use a tolerance-checked conical development that preserves lengths and UV coordinates, including degree-elevated straight rulings and roundoff-only rational weights. Genuinely varying rational weights are not normalized. Other parts and their following geometry use the engine selected by UV. Failures are identified and marked instead of silently switching flattening algorithms.
    5. Rerunning an already processed part preserves its part number and recoverable edge-dot identities, reuses its original label/group, and replaces its previous flat-group members after the new unroll succeeds. Existing flat labels recover the position of parts whose group contains only labels or dots. If several parts share a combined surface, their old faces are assigned back to their existing groups when every face is identified by an interior part label; the new geometry may have a different shape or face count. Ambiguous old joined geometry is retained with a warning, but every selected source is still unrolled into new output. Other existing parts update normally rather than creating another layout.

    Command-line options

    UV

    Yes by default delegates to native UnrollSrfUV; No uses RhinoCommon's developable Unroller directly with the document's tolerances, without queued command macros. Exact planar and conical development takes precedence in either mode, including joined parts made entirely of conical faces. Available during selection, following-geometry and placement prompts and remembered between runs.

    QuietNative

    experimental command-history cleanup, Yes by default. During native UV calls, defers painting of identified command-pane text controls until recognized English area-calculation progress, within-tolerance notices, routine surface counts and redundant native numerical area warnings have been removed. Earlier history, other warnings, errors, vTools' numbered final-area and edge discrepancies, and unknown/localized messages are preserved. No retains native output, with numerical area warnings qualified by part number. Available at all option prompts and remembered between runs.

    Labels

    creates Text, numbered Dots, or None for part identification. Reversible numeric labels receive the shared trailing-dot orientation mark without changing part numbers, rerun matching or edge-mate identities.

    RotateFlatParts

    rotates flat parts to roughly match the original source orientation as projected onto World XY, using both source label-frame directions when possible and the remaining direction for edge-on sources. Uses rotation only, not mirroring; labels, following geometry and mate dots move with the part. Otherwise keeps Rhino's unroller orientation. Reruns that preserve an existing part's placement retain its edited orientation.

    EdgeDots

    creates matching shared-edge M### dots for vMatch.

    Explode

    outputs separate flat faces instead of keeping each unrolled Brep joined.

    SplitFaces

    unrolls polysurface faces separately while retaining their source-face associations.

    KeepPropSurface

    preserves source surface object properties; otherwise uses the selected surface output layer.

    KeepPropFollowing

    preserves properties of following curves, points, and dots; otherwise uses the corresponding output layers.

    Spacing

    gap between automatically laid-out flat parts in model units.

    XExtents

    maximum layout row width in model units; 0 disables row wrapping.

    SurfaceLayer

    layer for committed flat surfaces, selected with the shared searchable layer picker.

    LabelLayer

    layer for committed labels, selected with the shared searchable layer picker.

    DotLayer

    layer for committed matching dots, selected with the shared searchable layer picker.

    Individual edge-length discrepancies exceeding the document absolute tolerance are reported by part and source edge (E1 is the first source topology edge), with a signed length in document units and a percentage of that source edge's length. Hidden transferred samples locate each edge on the actual flat geometry, including consecutive segments of a subdivided boundary; total perimeter and nearest-length guesses are not used. Edges that cannot be mapped are explicitly listed as unverified. Full-precision measurements are recorded in the diagnostic log.

    The source currently being processed is highlighted with lightweight outlined wires, and completed flat parts appear progressively in their final layout positions. Output creation keeps redraw suspended; previews update only the active viewport without automatically redrawing other views or the Layers panel. Refreshes combine newly finished parts with the latest source highlight. The first source is shown immediately; later updates adapt to rendering cost, targeting no more than about ten percent display overhead rather than forcing a refresh before every native call. The final result always refreshes all views and reports completed and failed sources. The in-place command prompt uses one stable format for part, completed count, percentage and failures without adding progress lines to history. Area discrepancies exceeding estimated measurement error are reported for each identified part, using the final flat geometry, with the signed difference in squared document units and percent. Rhino's own numerical area warnings are suppressed with QuietNative=Yes; with QuietNative=No they retain a part number and native unroll prefix, distinguishing them from the independent final-geometry check. Native output with an unexpected face count is rejected rather than replacing existing parts. QuietNative restores the progress prompt and releases its command-control paint guards after history cleanup, including on failure; it does not suspend viewport painting or input. If the command text controls cannot be identified, safe post-call cleanup remains available and routine output may briefly appear. Cleanup is skipped if the history was replaced/truncated, changes during filtering, or exceeds one million characters. Raw captured output remains available to diagnostics and other active output captures. Diagnostics record the selected engine, final counts, individual enable/draw/pump times, total live-display time and history-replay time for performance comparison.

    Options persist to vTools.config.json under the vUnrollSrf section. Layer choices are saved immediately when changed. The built-in Unrolled_surface and Unrolled_label layers use black with 69% display transparency; Unrolled_dot uses white with 69% transparency. Current/custom output layers are not restyled. The former vUnrollSrfUV command is consolidated into this command; use UV=Yes for that mode.

    vUzipCenter

    The vUzipCenter command offsets a U-shape's three curves inward, fillets the inside corners, and produces a single joined open curve.

    Steps

    1. Select three curves that form a U shape (left arm, right arm, bottom). You may preselect up to three curves before running the command; a fourth preselected curve is used as the initial boundary.

    Command-line options

    Left

    offset distance for the left arm.

    Right

    offset distance for the right arm.

    Bottom

    offset distance for the bottom curve.

    Radius

    fillet radius at the two inside corners.

    Distances accept fractional inch input (2 3/8, 2-3/8, 3/8, plain decimal) and the shorthand z/zipper (returns the left-arm default). Offset distances may be 0; radius must be greater than 0.

    1. A cyan preview curve is displayed showing the computed result.
    2. While previewing, adjust the same options to recompute live.
    3. Click any existing curve to set or replace the boundary: the result is trimmed or extended to meet it.
    4. Press Enter to accept and add the result curve to the document.

    The Options command-line option opens the shared hierarchical layer dropdowns with color swatches for center, glass, and vis output layers. Settings persist under the vUzipCenter section.
